# Conformance vectors

Each `<module>.json` file in this directory publishes one open module's worked examples
as plain-JSON test vectors: literal inputs for the module's registered entrypoint and the
output values those inputs must produce. An implementation of the same calculations in
any language can replay them: run your function on `inputs`, compare the result to
`expected` under the rules below. The repo validates every case against its own
implementations in `lib/openstartup/` on every test run, so a published vector is one the
reference implementation passes.

## File format

```jsonc
{
  "module": "antiDilution",            // the lib/openstartup module id
  "entrypoint": "applyAntiDilution",   // the registered entrypoint (registry.json documents its inputSchema)
  "implementation": {                  // the reference implementation these vectors were validated against
    "file": "lib/openstartup/antiDilution.ts",
    "sha256": "<sha256 of that file at generation time>"
  },
  "readme": "open-modules/conformance/README.md",
  "cases": [
    {
      "name": "springmeyer-broad-based",   // unique within the file
      "description": "...",                // the arithmetic in words, with the published figures
      "source": "...",                     // the citation the case replays (see Provenance)
      "tolerance": 0.005,                  // optional: absolute numeric tolerance; omitted = exact
      "inputs": [ ... ],                   // positional arguments for the entrypoint
      "expected": { ... }                  // partial deep match against the return value
    }
  ]
}
```

`../registry.json` carries each entrypoint's JSON Schema (`inputSchema`), so the shape of
`inputs` is machine-readable there; `inputs` here is the positional-arguments array that
schema describes.

## Comparison rules

`expected` is a partial deep match against the entrypoint's return value:

- **Objects**: every key listed in `expected` must match; keys the case does not list are
  ignored (results carry extra fields such as notes and review flags).
- **Arrays**: compared index by index and must have equal length. An empty object `{}`
  matches any element, so a case can pin one element of a longer array.
- **Numbers**: must land within the case's `tolerance` of the expected value (absolute
  difference); a case without `tolerance` requires exact equality. Exact-equality cases
  pin values the reference implementation produces as IEEE 754 doubles; an implementation
  in another numeric model should treat them as values to reach within its own epsilon.
- **Everything else** (strings, booleans, null): strict equality.

The reference comparator is `firstMismatch` in
`../../scripts/generate-conformance-vectors.ts`.

Where a module convention matters to the numbers, the vectors inherit it from the cited
source: share counts floor, prices round to 4 decimals (the YC guide's convention), cent
allocation is largest-remainder, and dates are UTC ISO strings.

## Provenance

Every case's `source` names the citation it replays: a published worked example (vendor
doc, agency example, statute or regulation example, or a practitioner article the module
header cites) or, for arithmetic the sources state as conventions rather than numbers,
the committed test that hand-derives it. Cases are generated by
`scripts/generate-conformance-vectors.ts`, which executes each case against the repo's
implementation before writing it; `__tests__/conformance-vectors.test.ts` fails if a
committed file drifts from regeneration or a committed case stops passing. Edit the case
definitions in the script, rerun it, and commit the output; the JSON files are generated
and are not edited by hand.

Two modules carry no vector file: `grant409aSanity` (its tests state there is
deliberately no published valuation example to replay; the module refuses to value
companies) and `capTableCodec` (a permalink encoding with round-trip tests, not numeric
arithmetic).
